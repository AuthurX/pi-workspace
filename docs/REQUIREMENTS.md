# 第一版需求

## 目标

用户在普通 WSL Shell 中执行一条命令，无需先进入交互式 Pi，即可补齐上次的 Pi 工作会话组合。交付物为一个 Pi package，包含自动登记扩展与独立 CLI；不调用模型。

- 项目目录：使用者可将仓库克隆到任意目录。
- npm 包名：`@ellieyujin/pi-reopen`；许可证为 MIT，版权人为 `ellieyujin`。无 scope 的 `pi-workspace` 属于其他作者，见 `PUBLISHING.md`。
- 外部入口：`pi-workspace restore`（已实现，端到端验收仍待完成）。
- 第一阶段环境：Windows WezTerm + Arch WSL。

## 已确认的恢复规则

以下三点由用户明确确认，作为第一版开发和验收依据：

1. **只恢复 Pi**：恢复关闭 WezTerm 时仍打开的 Pi 会话，不恢复 Pi 启动的开发服务器、构建任务、工具子进程或其他普通终端。
2. **恢复后等待用户输入**：重新启动 Pi，进入原目录并加载已保存的对话，然后等待用户操作。不自动发送“继续”、触发模型请求、重跑中断的工具命令或执行其他工作任务。
3. **提前单独关闭的不恢复**：在关闭整个 WezTerm 之前，用户已经单独退出或关闭的 Pi 不属于待恢复集合。不能把所有曾经登记过的会话累计为恢复清单。

例如：原本打开 A、B、C，先单独关闭 B，之后关闭 WezTerm；下次只恢复 A、C。即使 A、C 已完成回答、正在等待输入，只要关闭 WezTerm 时仍打开，也应恢复。

“接着做”指保留已经保存的文件修改并加载对话上下文，让用户接着输入；不意味着恢复已退出进程的内存现场、未保存的回答或工具执行中断点。包不得自动回滚或重放文件修改。

这是已确认的行为要求，不代表现有原型已实现；“主动退出与被动死亡”的可靠识别仍需技术设计和实际验证。

## 已确认的边界规则

以下六条为用户确认的默认方案（2026-10-30）：

1. **多窗口合并**：多个 WezTerm 窗口中的 Pi 合并为一个恢复集合，一起恢复。第一版不记录窗口归属。
2. **不还原窗口分组**：恢复时打开一个 WezTerm 窗口、多个标签页；不重建原窗口布局，标签顺序按记录顺序。
3. **关闭判定**：用户在 Pi 内主动退出（如 `/exit`）视为提前单独关闭，不恢复；Pi 因窗口关闭、崩溃、WSL 关机而被动死亡，视为随终端关闭，恢复。边界：`kill -9` 等手动强杀按被动死亡处理、会被恢复，接受此误差。
4. **崩溃安全**：工具持续把“当前存活 Pi 集合”实时写盘；崩溃、强制结束、断电不需要额外保存动作，磁盘上即为最新名单。
5. **重启恢复**：WSL/电脑重启后，恢复集合全部还原；失效的 PID 不得被误判为仍在运行。
6. **部分已开**：恢复时按会话文件识别，只补开缺失的 Pi；已在运行的会话跳过。连续或并发执行恢复命令不产生重复。

## 已确认的交互与数据规则

1. **触发方式**：第一版仅手动执行恢复命令；“打开终端自动恢复”留作后续可选功能，不在 P0。
2. **空窗口**：从未发送过消息的 Pi 窗口没有对话文件，恢复时跳过，并在结果中提示跳过数量；不重建空终端。
3. **旧记录迁移**：忽略旧原型产生的历史格式登记，不自动删除；新版本按新规则从零记录。提供 `clear` 方式手动清理，对话文件不受影响。
4. **命令与入口**：外部命令为 `pi-workspace restore`（后续可加 `list`、`doctor`、`clear`）；Pi 内 `/all` 与 `Ctrl+Shift+O` 过渡期保留，行为与 CLI 对齐，共用同一恢复逻辑。
5. **标签页标题**：优先使用会话名（`/name` 设置过），否则使用工作目录的文件夹名。

以上共 14 条规则构成需求基线；后续变更需更新本文档并同步测试。

## 功能范围

### P0：必须完成

1. **外部恢复**：普通 Shell 一条命令启动，无需额外交互式 Pi 作为入口。
2. **自动记录**：持续维护“当前存活 Pi 集合”，保存会话文件绝对路径、工作目录、会话名和运行身份，实时落盘。用户无需命名或手动保存工作区。
3. **上次组合语义**：恢复关闭 WezTerm 时仍打开的 Pi，包括已完成回答、正在等待输入的 Pi；提前单独退出或关闭的 Pi 不恢复。不是恢复所有历史上打开过的对话。启动一个入口 Pi 不得覆盖之前的恢复集合。
4. **生命周期**：按已确认判定实现——Pi 内主动退出（如 `/exit`）将成员移出集合；被动死亡（窗口关闭、崩溃、WSL 关机）保留在集合中。`/new`、`/resume`、`/fork`、`/reload` 的成员变化必须有明确设计和测试。识别机制不可靠时如实说明限制，不得宣称精确快照已实现。
5. **去重**：同一个会话文件只恢复一次；同目录不同会话分别保留。识别正在运行、正在启动的实例；连续或并发执行恢复命令不应重复创建标签页。
6. **安全启动**：进入原目录，以正确 WSL 发行版和用户启动 Pi；路径中的空格、引号、`$` 等字符保持原样。不在同一文件上无保护地创建多个 Pi 写入实例。
7. **环境预检**：检查 Pi、WezTerm、WSL 互操作、工作目录与会话文件。未通过不得批量启动；不自动 sudo、不自动修改系统配置。
8. **真实结果**：区分已运行、待恢复、缺失、启动失败；捕获同步异常和子进程失败，不把“发起请求”当成“Pi 已成功恢复”。
9. **持久化**：支持多实例并发和异常退出，防止记录互相覆盖。进程身份需覆盖 PID 重用及 WSL 重启情形。
10. **打包与安装**：同时提供 Pi 扩展入口和 npm `bin` 入口；明确 `pi install` 与外部 CLI PATH 的不同。安装/迁移不能造成重复加载。
11. **被动恢复**：只重新启动 Pi 并加载对话，恢复后等待用户输入。不自动继续工作，不重启关联服务、构建或工具子进程。
12. **空窗口与旧记录**：跳过无对话文件的空窗口并提示数量；忽略旧格式历史登记且不自动删除，按新规则从零记录。
13. **标签页标题**：优先会话名，无会话名时用工作目录的文件夹名。

### P1：辅助能力

- `list` / `--dry-run`：恢复前只读预览计划。
- `doctor`：检测运行环境并输出可操作的诊断。
- 手动补选近期对话：仅作旧登记丢失时的补救，不当作准确的上次工作区；须经用户确认。
- 打开终端自动恢复（Shell 钩子）：作为明确开启的可选项，不是默认行为。

## 不做

- 多套具名工作区（第一版不需要）。
- 修改 Pi 主程序，或通过替换安装文件实现 `pi -all`。
- 自动恢复其他普通 Shell、CMD、开发服务。
- 还原 WezTerm 窗口分组与布局；第一版统一为一个窗口多个标签页。
- 第一版自动执行恢复（自动恢复仅作为后续可选功能）。
- 复活已退出进程的内存、未完成模型请求、输入草稿、滚动位置。
- 第一版强依赖 Zellij/tmux；进程保活可后续增加后端。
- 由模型推测恢复清单或调用模型执行恢复。

## 验收场景

- 六个 Pi 与其他普通终端混用，关闭整个 WezTerm 后，从普通 Shell 恢复关闭时仍打开的 Pi 组合；非 Pi 终端不恢复。
- A、B、C 三个 Pi 中提前单独关闭 B，再关闭 WezTerm；下次只恢复 A、C。
- Pi 已完成回答并停在输入框等待，关闭 WezTerm 后仍恢复该会话，不能以是否正在生成判断成员。
- 恢复后各 Pi 加载原对话并等待输入；恢复流程不发送“继续”，不触发工作任务的模型请求，不重启原来的开发服务器或中断命令。
- 两个 WezTerm 窗口共五个 Pi，关闭后恢复为一个窗口五个标签页；窗口归属不恢复。
- A、B、C 中先在 Pi 内主动 `/exit` 关闭 B，再关闭 WezTerm：B 不恢复，A、C 恢复；用 `kill -9` 强杀 B 时 B 会被恢复（已接受的误差）。
- 崩溃、强制结束、断电后恢复：实时落盘的存活集合不丢失，恢复结果与正常关闭一致。
- 混有从未发消息的空 Pi 窗口：恢复时跳过并提示跳过数量，不重建空终端。
- 存在旧格式历史登记时：新版本忽略它们，不把历史累计集合误当上次组合恢复。
- 六个中已有两个运行，只补其余四个；连续执行、并发执行均不重复。
- 同目录两个不同对话均恢复；同一个文件路径的别名正确去重。
- WSL 重启后旧 PID 不会误判为运行中。
- 缺失/未落盘文件有明确报告，不创建空对话冒充恢复成功。
- WSLInterop 缺失时输出诊断，无未捕获的 ENOEXEC，无虚假成功。
- WezTerm 请求成功但 Pi 启动失败时仍能诊断。
- 多实例登记、关闭、reload、切换对话不会丢失或错误累计恢复成员。
- 包安装、升级、卸载和旧扩展迁移可回退，不触及认证与会话内容。
